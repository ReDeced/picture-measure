# Архитектура

Коротко: всё, что можно проверить без окна, живёт в библиотеке; в бинарнике
осталась только отрисовка.

```
src/
├── lib.rs        публичное API библиотеки
├── geometry.rs   прямоугольники и округление
├── model.rs      точки, прямоугольники, имена, подпапки
├── view.rs       преобразование экран ⇄ изображение (зум и панорама)
├── tools.rs      автомат жестов: клик / протяжка / Shift
├── pointer.rs    восстановление нажатий мыши из потока событий egui
├── history.rs    отмена и повтор
├── session.rs    весь конвейер: события → изменения разметки
├── json_io.rs    формат файла: чтение и запись
├── split.rs      экспорт по одному файлу на фигуру
├── main.rs       разбор аргументов и запуск окна
└── gui/          только рисование
    ├── app.rs    состояние окна, загрузка картинок, сохранение
    ├── canvas.rs отрисовка холста и раздача событий сессии
    └── panels.rs панели: панель инструментов, боковая, строка состояния
```

## Почему так разделено

Три требования, которые определили структуру:

1. **Поведение «клик = точка, протяжка = прямоугольник, Shift = квадрат» должно
   проверяться тестами.** Значит, оно не должно жить в коде отрисовки.
2. **Требуется несколько кнопок мыши одновременно** (левая рисует, средняя и
   правая панорамируют). `egui::Pointer` так не умеет, приходится разбирать
   поток `egui::Event` вручную.
3. **Картинки бывают большие, а фигур — тысячи.** Отсюда `f32` вместо `f64` и
   снапшоты вместо команд в истории отмены.

`src/gui/` не содержит ни одного теста бизнес-логики — только вызовы в
библиотеку и рисование.

## Поток кадра

```text
eframe::App::ui
  └─ gui::panels::frame
       ├─ handle_shortcuts        ← клавиатура
       ├─ handle_dropped_files    ← drag & drop
       ├─ handle_pending_loads    ← отложенные загрузки из CLI и drag & drop
       ├─ fit_view                ← если картинка ещё не вписана
       ├─ gui::panels::top_bar    ← отрисовка
       ├─ gui::panels::side_panel ← отрисовка
       ├─ gui::panels::status_bar ← отрисовка
       └─ gui::panels::central
            └─ gui::canvas::show
                 ├─ session.handle_events(events, modifiers, rect, backend_down)
                 ├─ paint(...)                        ← отрисовка
                 └─ context_menu(...)                 ← отрисовка
```

Обратите внимание: `session.handle_events` вызывается **до** отрисовки, а
`paint` читает уже обновлённое состояние сессии.

## `session::Session`

Центральный тип. Держит:

| Поле | Назначение |
|---|---|
| `set` | `AnnotationSet` — сами фигуры |
| `history` | Снапшоты для отмены |
| `selection` | Выделенные `id` |
| `view` | `ViewTransform` — зум и панорама |
| `canvas` | `CanvasState` — автомат жестов |
| `pointer` | `PointerInput` — состояние кнопок мыши |
| `new_folder` | Подпапка для новых фигур |
| `dirty`, `message` | Состояние для интерфейса |

### Конвейер обработки

```rust
pub fn handle_events(
    &mut self,
    events: &[Event],
    modifiers: egui::Modifiers,
    canvas: egui::Rect,
    backend_down: &[PointerButton],
) -> FrameChanges
```

1. `pointer.begin_frame()` — сбросить накопления текущего кадра.
2. `pointer.update(events)` — разобрать нажатия, отпускания, перемещения.
3. Если курсор над холстом — `handle_canvas(...)`.
4. Страховка: если жест идёт, а кнопка больше не нажата — отменить жест.

`backend_down` — список кнопок, которые, по мнению оконного бэкенда, реально
зажаты. Это авторитетный источник: при потере фокуса окна бэкенд перестаёт
слать события отпускания, и без этой проверки предпросмотр прямоугольника
залип бы навсегда.

### Эффекты

`handle_canvas` не меняет состояние напрямую, а возвращает список `Effect`:

```rust
enum Effect {
    Pressed(Pos2),   // приложение само разберётся, что под курсором
    AddPoint(Pos2),
    AddRect(Rect),
    Delete(ShapeId),
    Select(ShapeId),
    AddToSelection(ShapeId),
    RemoveFromSelection(ShapeId),
    MoveSelection(Vec2),
    Pan(Vec2),
    Zoom { factor: f32, anchor: Pos2 },
    …
}
```

Приём с «эффектами» позволяет проверять автомат жестов в тестах без
`egui::Context`, окна и текстуры: подайте события, получите эффекты, сравните
с ожиданием.

## Автомат жестов (`tools::CanvasState`)

```text
                    ЛКМ
Idle ─────────────────────────► Drawing { start }
  ▲                                │
  │                                │ ЛКМ вверх
  │         Pan ◄──────────────────┘
  │          ▲
  └──────────┘  СКМ / ПКМ / Alt+ЛКМ в любой момент
```

Решения:

- **Клик или протяжка?** Сравнивается путь указателя в *экранных* пикселях с
  `DRAG_THRESHOLD_SCREEN` (4 px). Воспринимаемая лёгкость движения не зависит от
  масштаба, поэтому порог измеряется на экране.
- **Квадрат?** Длина стороны — `max(|dx|, |dy|)`, направление роста — по
  знаку смещения. Квадрат растёт из точки нажатия в ту сторону, куда движется
  курсор.
- **Два нажатия?** Состояние `DragState::Moving` входит не из `on_press`, а из
  `Effect::Select` / `Effect::AddToSelection`: только приложение знает, что
  фигура выбрана и её можно таскать.
- **Отпускание без последнего `PointerMoved`?** При отпускании позиция
  дорисовывается: и для перетаскивания фигуры, и для панорамы. Быстрый
  «флик» не теряет последние пиксели.

## Трансформация вида (`view::ViewTransform`)

```text
screen = image * scale + offset
image  = (screen - offset) / scale
```

Обе операции обратимы с точностью до `f32`, поэтому координаты фигуры не
зависят от зума и панорамы.

- `zoom_by` удерживает экранную точку на том же пикселе картинки.
- `fit` центрирует картинку с отступом 4%.
- `grid_step` подбирает «круглый» шаг сетки (1, 2, 5 × 10ⁿ), чтобы линии не
  слипались ни при каком масштабе.

## Указатель (`pointer::PointerInput`)

`egui::Pointer` отслеживает только основную кнопку. `PointerInput` разбирает
`Event::PointerButton` и `Event::PointerMoved` и ведёт таблицу
`Vec<(PointerButton, HeldButton)>` — их всего три, поэтому линейный поиск
быстрее и проще хеш-таблицы.

## История (`history::History`)

Снапшоты всего `AnnotationSet`, максимум 128. Для тысяч фигур это несколько
сот килобайт на состояние — приемлемо и заметно надёжнее, чем команды с
инверсией.

Запись состояния происходит **до** изменения, поэтому `undo` просто подставляет
предыдущий снапшот.

## Формат (`json_io`, `split`)

- `Number` — `#[serde(untagged)]` перечисление `Int(i64)` / `Float(f64)`, чтобы
  целые координаты писались как `120`, а не `120.0`.
- `round_to` работает в `f64`, иначе `12.3456` с двумя знаками превратилось бы в
  `12.3500004`.
- При чтении `type` хранится строкой и разбирается вручную: опечатка
  (`"poligon"`) даёт понятное сообщение, а не ошибку serde.
- `split::plan` — чистая функция: превращает набор фигур в список
  `(относительный путь, содержимое)`. Запись на диск — отдельно, поэтому
  раскладку можно полностью покрыть тестами.

## Тесты

| Уровень | Где | Что покрывает |
|---|---|---|
| Модульные | `#[cfg(test)]` в `src/` | Геометрия, имена, папки, JSON, автомат жестов, указатель, история |
| Сессионные | `src/session.rs` | Полный конвейер: события → фигуры → отмена |
| Сквозные | `tests/session_flow.rs` | Сценарии пользователя, экспорт, повторное чтение, раздельный экспорт |
| Формат | `src/json_io.rs` | Каждая ветка разбора и каждая ошибка |

Тесты не открывают окно и не создают текстур, поэтому `cargo test` работает на
CI без виртуального дисплея.

## Что стоит помнить при изменении кода

- **Координаты — только в пикселях картинки.** Экранные координаты не должны
  попасть в модель.
- **`id` не переиспользуются.** Иначе имена начнут совпадать после удаления.
- **Авто-имя и пользовательское имя — разные вещи.** При чтении файла имя,
  совпадающее с авто-именем, не должно становиться пользовательским, иначе
  после round-trip имя перестанет следовать за номером.
- **Отрисовка не должна менять состояние.** Иначе поведение начнёт зависеть от
  частоты перерисовки.
