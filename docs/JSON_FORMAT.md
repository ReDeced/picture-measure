# Формат JSON

Программа пишет и читает один формат — `picture-measure`, версия `1`.
Координаты всегда в **пикселях исходной картинки**, начало отсчёта — **левый
верхний угол**, ось `x` направлена вправо, ось `y` — вниз. Значения не зависят от
того, как сильно пользователь увеличил картинку в программе.

## Общий вид файла

```json
{
  "format": "picture-measure",
  "version": 1,
  "image": {
    "path": "/home/user/photos/cat.png",
    "name": "cat.png",
    "width": 1920,
    "height": 1080
  },
  "settings": {
    "coordinate_system": "pixel",
    "origin": "top-left"
  },
  "folders": ["eyes", "faces"],
  "counts": { "total": 3, "points": 1, "rects": 2 },
  "annotations": [
    { "type": "point", "name": "point_1", "id": 1, "folder": "eyes", "color": "#ff5c5c", "x": 120, "y": 80 },
    { "type": "rect",  "name": "nose",    "id": 2, "folder": "faces", "x": 300, "y": 240, "width": 90, "height": 70 },
    { "type": "rect",  "name": "rect_3",  "id": 3, "color": "#40c4ff", "x": 10, "y": 20, "width": 100, "height": 100 }
  ]
}
```

| Поле | Тип | Обязательное | Значение |
|---|---|---|---|
| `format` | строка | нет при чтении | Всегда `"picture-measure"` |
| `version` | число | нет при чтении | Всегда `1` |
| `image` | объект | нет | Где и какого размера картинка |
| `image.path` | строка | нет | Полный путь, если картинка открывалась с диска |
| `image.name` | строка | нет | Имя файла вместе с расширением |
| `image.width`, `image.height` | число | нет | Размер в пикселях |
| `settings.coordinate_system` | строка | нет | Всегда `"pixel"` |
| `settings.origin` | строка | нет | Всегда `"top-left"` |
| `folders` | массив строк | нет | Отсортированный список всех непустых подпапок |
| `counts` | объект | нет | Сводка: `total`, `points`, `rects` |
| `annotations` | массив | нет (по умолчанию `[]`) | Фигуры в порядке создания |

`folders` и `counts` — это удобная сводка. Если её нет или она устарела, ничего
не сломается: программа считает всё по массиву `annotations`.

> При чтении программа принимает и «голый» массив фигур без обёртки —
> удобно для файлов, написанных руками:
>
> ```json
> [
>   { "type": "point", "name": "нос", "x": 10, "y": 20, "folder": "лицо" }
> ]
> ```

## Фигура

Общие поля у точки и прямоугольника:

| Поле | Тип | Обязательное | Значение |
|---|---|---|---|
| `type` | строка | да | `"point"` или `"rect"` |
| `name` | строка | нет | Имя фигуры. Если совпадает с авто-именем, считается авто-именем |
| `id` | число | нет | Сквозной номер фигуры. Если есть — именно он попадёт в `id` |
| `folder` | строка | нет | Подпапка. Пустая строка не пишется вообще |
| `color` | строка | нет | Цвет в виде `#rrggbb` |
| `x` | число | да | Точка: координата X. Прямоугольник: левый край |
| `y` | число | да | Точка: координата Y. Прямоугольник: верхний край |

Только у прямоугольника:

| Поле | Тип | Обязательное | Значение |
|---|---|---|---|
| `width` | число | да | Ширина в пикселях, всегда ≥ 0 |
| `height` | число | да | Высота в пикселях, всегда ≥ 0 |

### Точка

```json
{ "type": "point", "name": "point_1", "id": 1, "x": 120, "y": 80 }
```

### Прямоугольник

```json
{ "type": "rect", "name": "rect_2", "id": 2, "x": 300, "y": 240, "width": 90, "height": 70 }
```

`x` и `y` — это **левый верхний** угол, а не центр. Программа никогда не пишет
отрицательных `width`/`height`: если потянуть мышью вверх-влево, значения всё
равно окажутся положительными, а начало сместится влево-вверх.

### Числа

Целые значения пишутся без дробной части (`120`, а не `120.0`), дробные — с той
точностью, что выбрана в панели «Экспорт» (по умолчанию 2 знака, можно от 0 до 4).
Значение `12` и `12.0` для любого потребителя JSON одинаковы.

### Имена

По умолчанию `point_N` или `rect_N`, где `N` — сквозной номер фигуры (`id`).
Номера не переиспользуются после удаления: если удалить `point_1`, следующая точка
станет `point_3`, а не `point_2`. Это гарантирует, что имена уникальны.

Если в файле `name` совпадает с авто-именем для этого `id`, программа считает его
авто-именем, а не пользовательским. Поэтому после round-trip
`point_5 → point_7 → point_5` авто-имя снова начнёт следовать за номером.

Кнопка «Перенумеровать» присваивает номерам последовательные значения
(`1, 2, 3, …`), не трогая пользовательские имена.

### Подпапки

`folder` — свободная строка. Программа нормализует разделители (`\` → `/`) и
обрезает пробелы. Вложенность поддерживается: `faces/eyes/left` станет папкой
`faces/eyes` с файлом `left.json` при раздельном экспорте.

## Ошибки чтения

Программа не падает на плохом файле, а показывает понятное сообщение:

| Что в файле | Сообщение |
|---|---|
| Невалидный JSON | `некорректный JSON: …` |
| Не объект и не массив | `неподдерживаемая структура файла: …` |
| У прямоугольника нет `width` | `фигура №N: у прямоугольника отсутствует поле "width"` |
| У прямоугольника нет `height` | `фигура №N: у прямоугольника отсутствует поле "height"` |
| `type: "polygon"` | `фигура №N: неизвестный тип фигуры "polygon" …` |
| Нет `type` | `фигура №N: не указан тип фигуры …` |
| `width: -1` | `фигура №N: отрицательный размер прямоугольника (-1, 2)` |

Неизвестные поля игнорируются — файл из более новой версии программы с
дополнительными полями прочитается нормально.

Если `type` отсутствует, но есть `width`/`height`, фигура считается
прямоугольником.

## Раздельный экспорт

Кроме одного файла есть режим «каждая фигура отдельным файлом» с раскладкой по
подпапкам:

```
out/
├── eyes/
│   ├── left_eye.json
│   └── right_eye.json
├── faces/
│   └── nose.json
└── rect_3.json
```

Каждый такой файл — полноценный документ формата, просто с одной фигурой.
Имя файла получается из имени фигуры; небезопасные символы (`/ \ : * ? " < > |`)
заменяются на `_`, пробелы в начале и конце обрезаются. Если два файла
столкнулись бы по имени, ко второму добавляется `_2`, к третьему `_3`.
Компоненты вида `..` и абсолютные пути отбрасываются, так что экспорт не может
выйти за пределы указанной папки.

## Примеры для Python

### Чтение

```python
import json

with open("annotations.json", encoding="utf-8") as f:
    data = json.load(f)

image = data.get("image", {})
print(f"{image.get('name')}: {image.get('width')}×{image.get('height')}")

for a in data["annotations"]:
    folder = a.get("folder", "")
    if a["type"] == "point":
        print(f"  точка  {folder + '/' if folder else ''}{a['name']}: ({a['x']}, {a['y']})")
    else:
        cx = a["x"] + a["width"] / 2
        cy = a["y"] + a["height"] / 2
        print(f"  прямоугольник {a['name']}: {a['width']}×{a['height']} @ ({cx:.1f}, {cy:.1f})")
```

### Группировка по подпапкам

```python
from collections import defaultdict

groups = defaultdict(list)
for a in data["annotations"]:
    groups[a.get("folder", "")].append(a)

for folder, items in sorted(groups.items()):
    print(folder or "(без папки)", len(items))
```

### Подготовка к YOLO

```python
w, h = image["width"], image["height"]
for a in data["annotations"]:
    if a["type"] != "rect":
        continue
    xc = (a["x"] + a["width"] / 2) / w
    yc = (a["y"] + a["height"] / 2) / h
    nw = a["width"] / w
    nh = a["height"] / h
    print(f"{a.get('folder', 'object')} {xc:.6f} {yc:.6f} {nw:.6f} {nh:.6f}")
```

### Свой файл для чтения программой

```json
[
  { "type": "point", "name": "левый_зрачок", "x": 120, "y": 80, "folder": "eyes" },
  { "type": "rect",  "name": "зрачок", "x": 110, "y": 70, "width": 22, "height": 22, "folder": "eyes" }
]
```

Сохраните такой файл рядом с картинкой и откройте:
`picture-measure photo.png eyes.json`.
